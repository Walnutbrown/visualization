# 관계·과정 그림

위치·연결·대조·변화에서 무엇을 읽어야 하는지 정한다. 단순 계층·정방향 관계는 로컬 `diagram`, 비교는 `compare`, 순차적 상태는 `steps`를 먼저 검토한다. 계약은 `components.md`에 있다.

- 포함·원인·참조·순서의 차이를 라벨·화살표로 드러낸다. 실제로 없는 연결을 만들지 않는다. 관계를 전달하지 않는 텍스트 상자 나열은 시각적 설명으로 보지 않는다.
- 복잡한 전체 구조는 개요와 부분 그림으로 나눈다. 노드 수를 맞추려고 의미 있는 관계를 자르지 않는다.
- 긴 라벨·형제 노드·교차 연결이 많으면 다른 배치나 분할을 선택한다. 작은 화면에서 글자를 줄이는 것으로 해결하지 않는다.
- 전후 상태를 비교하는 과제는 나란한 정적 그림을 우선한다. 변화 자체나 대상의 이동을 추적해야 하면 단계별 정지 그림을 그리고 `steps`의 `data-scrub`으로 잇는다.
- 직접 SVG를 작성할 때는 viewBox, role="img", 고유한 title·desc와 aria-labelledby를 제공한다. 실제 크기에서 읽히는 라벨, 의미가 있는 모양·선을 사용한다.
- 연결선은 출발·도착 경계에 닿게 하고, 글자와 관계없는 도형을 가로지르지 않게 한다. 선·곡선에는 fill="none"을 명시한다. 화살표 방향·머리·의도하지 않은 검은 면을 실제 렌더링으로 확인한다.
- 그림 가까이 핵심 관계·조건·출처를 짧게 둔다. 본문을 읽지 않아도 주요 구조가 보이고, JS가 꺼져도 핵심 설명을 읽을 수 있게 한다.

scrub은 단계 그림 사이를 직선으로 잇는다. 연속 물리 운동(포물선, 진동)·명령 구조가 다른 경로 모핑·순환 관계는 기본 부품의 지원 범위를 넘는다. 정적 연속 그림 또는 검증한 로컬 코드를 사용한다. 스테퍼 재생을 연속 운동의 정확한 시뮬레이션처럼 제시하지 않는다.

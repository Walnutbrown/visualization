# 스크롤리텔링 (`scrollytelling`)

인터랙션 · 과제: 서사 안내, 시간에 따른 변화, 탐색 지원 · 데이터: 시간, 수치형, 범주형, 지리 · 형태: -

스크롤에 따라 시각화 상태가 변화하며 이야기를 전달하는 내러티브 기법.

출처: https://vis.hwpark.net/catalog/scrollytelling/

## 언제 사용하나

- 독자를 일련의 분석적 통찰을 통해 안내하는 것이 목표인 데이터 저널리즘과 에디토리얼 콘텐츠에서.
- 데이터 이야기가 시작, 중간, 끝이 있는 명확한 선형 내러티브를 가질 때.
- 청중이 일반 대중이거나 비전문가여서 열린 탐색 도구로부터 이득을 얻지 못할 때.
- 시각화가 순차적으로 쌓이는 4~15개의 의미 있는 상태를 가질 때.
- 저자가 속도와 초점을 통제하는 것이 이야기에 유리할 때(설명형 모드).

## 이럴 땐 피하세요

- 청중이 데이터를 자유롭게 탐색하고 싶어할 때: 스크롤리텔링은 본질적으로 저자 주도적입니다.
- 시각화에 상태가 1~2개뿐일 때(이 패턴을 정당화할 만큼 전환이 충분하지 않습니다).
- 콘텐츠가 정적인 주석 차트나 짧은 애니메이션으로 더 잘 작동할 때(스크롤 기반 속도 조절이 필요하지 않습니다).
- 의미 있는 지점을 만들 만큼 스크롤 거리가 충분하지 않은 매우 짧은 페이지에서.
- 접근성이 주된 관심사일 때: 세심한 ARIA 주석이 추가되지 않으면 스크린 리더와 키보드만 사용하는 사용자는 스크롤로 촉발되는 시각적 변화를 놓칠 수 있습니다.

**함께 쓰면 좋은 기법:** `area-graph`, `bar-chart`, `bubble-chart`, `choropleth`, `line-graph`, `sankey-diagram`, `scatterplot`, `stacked-bar-chart`

**관련 기법:** `animated-transition`, `focus-and-context`, `hover-highlight`, `tooltip`

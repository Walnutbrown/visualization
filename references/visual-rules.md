# 시각화 규칙과 검수 체크리스트

모든 시각화(차트, 다이어그램, 인포그래픽, 상호작용 모델)를 작성할 때 이 규칙을 준수합니다.
`vis.hwpark.net`의 95개 기법과 20개 원칙 스냅샷이 `references/vis/`에 로컬로 보관되어 있습니다.

---

## 1. 사용 순서

1. **데이터 구조와 전달 목적 분석**: 전달하려는 데이터의 차원(범주형, 연속형, 시계열, 관계망 등)과 핵심 질문(비교, 분포, 구성비, 상관, 흐름 등)을 정의합니다.
2. **기법 선정**: 아래 [데이터 구조 → 시각화 기법 매핑 표](#2-데이터-구조--시각화-기법-매핑)에서 기법을 선택합니다. 목록에 없는 경우 `references/vis/catalog.md`의 과제 태그로 검색합니다.
3. **제약 및 대안 검토**: 선택한 기법의 `references/vis/techniques/<slug>.md`에서 **이럴 땐 피하세요**와 **구조**를 확인하고, 부적합할 경우 대안 기법으로 전환합니다.
4. **구현 방식 결정**:
   - 내장 부품이 있는 경우: `data-illustrate="<부품>"` 속성을 지정합니다 (`chart`, `diagram`, `steps`, `focus`, `model`, `waterfall`, `histogram`, `heatmap`, `venn`).
   - 내장 부품이 없는 경우: `references/diagram.md`의 SVG 규칙에 따라 시맨틱 인라인 SVG로 구현합니다.
5. **원칙 검수**: 아래 [20대 원칙 체크리스트](#3-20대-원칙-체크리스트)와 [화면 디자인 점검](#4-화면-디자인-점검)으로 검수를 완료합니다.

## 2. 데이터 구조 → 시각화 기법 매핑

| 데이터 구조 | 대표 사례 | 기법 `slug` | 권장 부품/방식 | 피할 때 → 대안 |
|---|---|---|---|---|
| **범주별 크기·순위** | 범주별 수치 비교, 순위 | 막대 `bar-chart`, 클리블랜드 점 도표 `cleveland-dot-plot` | `chart` bar | 정밀한 개별 수치 조회 → 표 |
| **시작값 → 증감 → 누계** | 재무제표 현금흐름, 예산 증감 | 폭포 차트 `waterfall-chart` | `waterfall` | 누적 인과관계 없음 → 막대 |
| **전체 대비 부분의 비율** | 포트폴리오 비중, 시장 점유율 | 누적 막대 `stacked-bar-chart`, 와플 `waffle-chart`, 파이 `pie-chart` | 인라인 SVG | 범주 6개 이상이거나 차이가 미미할 때 → 내림차순 정렬 막대 |
| **연속적 시간 변화** | 시계열 추세, 지표 변화 | 선 그래프 `line-graph` | `chart` line (커서 탐침) | 순서 없는 이산 범주 → 막대 |
| **두 시점·조건 비교** | 전후 비교, 정책 효과 | 기울기 차트 `slope-chart`, 덤벨 차트 `dumbbell-chart` | 인라인 SVG | 비교 시점 3개 이상 → 선 그래프 |
| **두 변수 간 상관** | 상관관계, 산포, 이상치 탐지 | 산점도 `scatterplot` | `chart` scatter | 상관을 인과로 비약하지 않음 |
| **단일 변수의 분포** | 값의 밀도, 왜도, 빈도 | 히스토그램 `histogram` | `histogram` | 데이터 20건 미만 → 점 도표 또는 스트립 플롯 |
| **집단 간 분포 비교** | 그룹별 분포 및 분위수 대조 | 박스 플롯 `box-plot`, 스몰 멀티플 `small-multiples` | 인라인 SVG | 2개 집단 정밀 대조 → 동일 축 히스토그램 대조 |
| **불확실성 및 범위** | 신뢰구간, 추정 오차, 편차 | 오차 막대 `error-bars`, 범위 차트 `span-chart` | 인라인 SVG | 오차 유형(표준오차/표준편차/95% CI) 명시 필수 |
| **행 × 열 2차원 패턴** | 상관 행렬, 혼동 행렬, 히트맵 | 히트맵 `heatmap`, 상관 행렬 `correlation-matrix` | `heatmap` | 격자 칸이 지나치게 적음 → 숫자 표 |
| **집합 간 교집합/포함** | 교집합, 벤 다이어그램 | 벤 다이어그램 `venn-diagram` | `venn` | 집합 4개 이상 → 업셋 플롯(UpSet) 또는 행렬 |
| **계층·트리 구조** | 계통도, 디렉터리, 조직도 | 덴드로그램 `dendrogram`, 아이시클 `icicle-diagram` | `diagram` 계층 | 면적 비중까지 표현 → 트리맵 `treemap` |
| **네트워크·관계망** | 관계도, 상태 전이, 토폴로지 | 네트워크 `network-diagram`, 인접 행렬 `adjacency-matrix` | `diagram`, `heatmap` | 밀도가 높거나 순환이 복잡함 → 인접 행렬 |
| **양의 흐름 및 전환** | 유입-이탈, 전환 퍼널, 자금 흐름 | 샌키 `sankey-diagram`, 퍼널 `funnel-chart` | 인라인 SVG | 단순 단계별 감소율 → 퍼널 |
| **시간 순서의 일정/사건** | 타임라인, 프로젝트 일정 | 타임라인 `timeline`, 간트 차트 `gantt-chart` | 인라인 SVG | 동시 수행 및 종속 관계 강조 → 간트 |
| **단계별 절차 및 전이** | 알고리즘 실행, 상태 변화 | 스테퍼 `stepper`, 재생 스크러빙 `playback-scrub` | `steps` (`data-scrub` 지원) | 두 상태 비교가 주목적 → 나란히 정적 배치 |
| **수학/동적 매개변수 조작** | 파라미터 변화에 따른 곡선/출력 | 매개변수 조작 `parametric-manipulation` | `model` (동적 슬라이더) | 모델이 없는 정적 데이터 → 정적 차트 또는 비교 |
| **여러 뷰의 연동 탐색** | 식 ↔ 그래프 ↔ 표 연동 강조 | 연동 하이라이팅 `coordinated-highlighting` | `focus` | 단순 단일 시각화에는 미적용 |

## 3. 20대 원칙 체크리스트

모든 시각화 작성 시 다음 20개 핵심 원칙을 확인합니다 (`references/vis/principles/` 참조).

### 접근성 (Accessibility)
- [ ] **색 외의 2차 단서 (`accessibility`)**: 색상뿐 아니라 라벨, 점선/실선 패턴, 기호, 위치로 구별 가능해야 합니다.
- [ ] **명도 대비**: 일반 텍스트 4.5:1 이상, 큰 텍스트(18pt/24px) 3:1 이상, 핵심 그래픽 요소(선, 막대 테두리) 3:1 이상을 확보합니다.
- [ ] **대체 텍스트 및 시맨틱 태그**: 정보성 SVG는 `role="img"`, `<title>`, `<desc>`를 포함하며, 표 형태의 백업(`data-fallback`)을 제공합니다. 장식 요소는 `aria-hidden="true"`.
- [ ] **키보드 접근성**: 인터랙티브 요소는 Tab 포커스 및 Enter/Space로 조작 가능해야 합니다.

### 구성 및 스토리텔링 (Composition & Storytelling)
- [ ] **직접 라벨링 (`annotation-design`)**: 별도의 범례 상자보다 데이터 포인트나 선 옆에 직접 라벨을 붙입니다. 의미 있는 기준선(평균, 임계값)을 표시합니다.
- [ ] **시각적 일관성 (`consistency`)**: 동일한 개념이나 범주는 전체 화면에서 동일한 색상, 명칭, 기호를 유지합니다.
- [ ] **결측치 표시 (`empty-states`)**: 결측치는 0으로 채우지 않고 끊어진 선이나 빈 영역으로 표시합니다.
- [ ] **의도적 기본값 (`intentional-defaults`)**: 기본 정렬은 내림차순 또는 시계열 순서로 설정하며, 핵심 메시지가 첫 화면에서 드러나도록 강조합니다.
- [ ] **디자인 토큰 준수 (`limit-your-choices`)**: 임의의 hex 색상이나 px 단위를 남발하지 않고 `base.css`의 CSS 변수 토큰을 사용합니다.
- [ ] **점진적 공개 (`progressive-disclosure`)**: 큰 그림을 5초 이내에 파악할 수 있도록 하고, 상세 데이터는 인터랙션이나 보조 영역으로 분리합니다.
- [ ] **스몰 멀티플 (`small-multiples-principle`)**: 다중 패널 비교 시 x/y축 스케일을 동일하게 고정하고 공통 축 라벨을 일원화합니다.
- [ ] **시각적 위계 (`visual-hierarchy`)**: 1차(핵심 데이터/주석) > 2차(축, 라벨) > 3차(격자선, 배경)로 명도와 굵기를 차등화합니다.

### 색상 (Color)
- [ ] **보조로서의 색채 (`color-as-supporting`)**: 주된 정보는 위치와 길이로 전달하고, 색상은 강조 및 보조 수단으로만 사용합니다. 흑백으로 출력해도 핵심이 식별되어야 합니다.
- [ ] **목적별 색상 체계 (`color-theory`)**: 범주형(구별되는 5~7색 이하), 순차형(단일 색조의 명도 단계), 발산형(양 끝 극단과 중립 0)을 목적에 맞게 적용합니다. 빨강-초록 단독 대조는 지양합니다.

### 데이터 무결성 (Integrity)
- [ ] **맥락 중심 (`context-over-decoration`)**: 장식용 3D 효과, 입체 그림자, 화려한 그라데이션을 배제하고 기준선과 출처를 명시합니다.
- [ ] **데이터-잉크 비율 극대화 (`data-ink-ratio`)**: 불필요한 테두리, 진한 배경 격자, 중복 라벨을 제거합니다.
- [ ] **단일 메시지 집중 (`less-is-more`)**: 한 시각화에 1개의 핵심 질문을 담고, 데이터 계열이 5개를 초과하면 분할합니다. 이중 y축은 원칙적으로 금지합니다.

### 지각 및 레이아웃 (Perception & Layout)
- [ ] **게슈탈트 원리 (`gestalt-principles`)**: 근접성, 유사성, 연속성, 폐쇄성을 활용해 관련 데이터를 자연스럽게 그룹화합니다.
- [ ] **그리드 및 정렬 (`grid-and-alignment`)**: 모든 텍스트와 축은 왼쪽 정렬 또는 기준선에 정확히 정렬합니다.
- [ ] **반응형 뷰포트 (`responsive-visualization`)**: 320px 모바일 화면부터 1920px 대화면까지 가로 스크롤 없이 유연하게 적응합니다. SVG `viewBox`를 활용합니다.
- [ ] **여백의 미 (`white-space`)**: 막대 폭 대비 여백 50~100%, 텍스트와 그래픽 간 충분한 호흡 공간을 보장합니다.

### 타이포그래피 (Typography)
- [ ] **단일 서체 및 위계 (`typographic-hierarchy`)**: Spoqa Han Sans Neo 단일 서체를 사용하며, 제목(Bold 700), 소제목/강조(Medium 500), 본문/축 라벨(Regular 400)의 3~4단계로 정돈합니다.

## 4. 화면 디자인 점검 (Hallmark 기준)

- **상자 속 상자 금지**: 외곽 테두리 상자 안에 또다시 테두리 박스를 중첩하지 않습니다.
- **틀에 박힌 이모지/화살표 제거**: 아이콘 대신 시맨틱한 기호나 텍스트를 사용합니다.
- **불필요한 대문자/자간 확대 금지**: 영문 텍스트의 과도한 자간 확장을 지양합니다.
- **가로 넘침(Horizontal Overflow) 금지**: 모든 화면 크기에서 전체 페이지 가로 스크롤이 발생하지 않아야 합니다.
- **가짜/임의 데이터 금지**: 실측 데이터와 명확한 출처를 표기합니다.
